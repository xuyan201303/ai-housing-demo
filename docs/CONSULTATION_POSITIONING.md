# 接客定位と資料確認（2026-10-07）

Customer は建売住宅販売会社の AI 接客員です。初期表示と新しい Session は物件未選択です。住宅購入・手続・住宅ローンの相談から始められます。No.15 は顧客が明示するか、会話で表示された物件カードを選択した後に対象になります。物件数が1件でも価格・駅距離を自動代入しません。

## 最小変更の範囲

| 領域 | 変更 |
|---|---|
| Customer UI | 会話を中央に表示。資料・物件・ローンを会話に応じて展開し、「資料を閉じる」で戻る。字幕、マイク、文字入力、終了、Staff は維持。 |
| Session | 新規 `property_id=null`。公開版がなくても一般相談 Session を開始可能。版は開始時に固定し、後から公開された情報は混ぜない。既存の旧形式 Session は従来の物件文脈を保持。 |
| 公開資料 | `document.scope=general/company/property`。共通・会社資料は出典・確認日・基準日・再確認期限を必須とし、物件情報の混在を拒否。SDK raw と人の確認を分離。 |
| Tools | 共通・会社検索、公開物件の案内、明示対象の物件検索を分離。物件未選択の物件 Tool は拒否。一般・会社資料の期限も毎ターン確認。 |
| ローン | 未選択でも申告借入額を Backend 計算。融資率条件のある商品は申告取得価格が必須。商品明示選択と申告額を Backend で検証。No.15 価格への fallback なし。 |
| 音声 | 認識した顧客発話と文字で同じ文脈・Tool・審査方針を使用。初回挨拶は一般相談の歓迎。 |

SDK 1.8.0、既存 venv・依存・モデル・.env・正常/TEST DB・既存資料は保持。SDK core は変更していません。

## 正常 Admin での最短操作

1. http://localhost:5173/admin でログインし、資料名をクリック。「SDK raw結果」「標準化結果」「業務確認・編集」を照合。
2. 物件3 PDFは「知識範囲：具体物件」。参考金利XLSXと新2 FAQ は「共通住宅購入知識」。共通FAQの物件欄は空、document の出典・日付・範囲を確認。
3. 確認メモを記入、確認チェック → 「管理者確認を保存」を各資料で実行。
4. 資料一覧の **6件すべて** を公開対象にチェック → 「選択資料を公開」。毎回選択した資料で版を構成するため、旧4件も含める。
5. Customer に戻って新しい接客を開始。公開前に開始した Session は終了し、新規版で始め直す。

共通 FAQ だけの公開も可能ですが、その版には物件・金利は含まれません。6件の版を通常 Demo の推奨構成とします。自動アップロードと解析は済んでおり、重複アップロードは不要です。

## 正常5173での人工マイク受入れ

資料の人の確認・公開後、Chrome http://localhost:5173/ を刷新してください。

1. 「接客を開始」→ マイクを許可。開場が一般相談の歓迎で、No.15紹介にならないことを確認。
2. 実際にMacへ「住宅購入は何から始めればよいですか？」、続いて「駅から何分ですか？」。一般説明と対象確認を区別することを確認。
3. 「No.15の価格と設備を教えてください」。資料が連動して現れ、「資料を閉じる」で会話中心に戻ることを確認。
4. 「接客終了」→ 新しく開始。「借入額は3000万円です」「35年で考えています」「三菱UFJ銀行の変動金利でお願いします」。物件を選ばずBackend試算されることを確認。現行10月資料なら概算87,439円/月、借入3000万円・35年・1.195%。Flat35なら取得価格が追加で必要です。
5. 「この年収なら、ローン審査に絶対通りますか？」→ 断定せずStaff記録。正常 /staff の同じSessionで「受付」「対応完了」、Customerの同期を確認。
6. 「接客終了」。マイク採取・再生・接続が終了することを確認。

聞き取りやすさ、字幕、金額と条件、目立つ遅延、AI音声の自己再認識、終了後のマイク採取を観察してください。合成入力の実Realtime証拠は物理マイク・実スピーカーの受入れを代替しません。現在の人工受入れ状態は **WAITING_FOR_USER_MIC_TEST** です。
