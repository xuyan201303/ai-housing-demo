# Phase 2 第2輪：資料更新と公開

対象は、一つの資料の更新を準備し、現在の公開集合から次版を作る業務です。
通常の資料更新と「対客利用を停止する」操作は別です。更新の準備・下書き保存・新改訂の確認では、既存の有効な公開内容を取り下げません。期限切れや明示的な用途撤回は引き続き即時制限されます。

## 社員の操作

1. 「資料管理」で変更する資料を開きます。
2. 原ファイルを使って登録内容だけ変更する場合は、先に「更新理由」を入力してから「登録内容を修正する」を選びます。新ファイルの場合も更新理由を入力し、「新しいファイルに差し替える」を選びます。開いていた旧資料と確認改訂が差し替え元として明示的に関連付けられます。
3. 新ファイルは SDK 解析を実行し、原資料と候補フォームを照合します。登録内容だけの変更は既存の SDK 証拠を使います。再解析したものとして記録しません。
4. 内容を編集して「下書きを保存」。金利の登録条件は「適用条件」の行ごとに追加・修正・削除できます。自由記載、借入額・年数等の数値条件とは別に保存されます。
5. 内容、出典、期限、資料用途、知識範囲を照合し、チェックを自分で付けて改訂を確認します。ここではまだ公開されません。
6. 「公開管理」→「現在の公開版から草案を作成」。現在の公開版に含まれる資料と確認改訂を基に、追加・差し替え・除外する資料だけを指定します。他の有効な資料は保持されます。
7. 「公開草案を保存」→「公開前の差分を確認」。資料集合と主要項目の変更前後、接客機能への影響を照合します。問題を解消し、「公開差分と注意事項を確認しました」を自分でチェックして「この内容で新しい版を公開」を押します。

確認・保存・公開の状態は別です。新しい接客は新しい公開版を使い、未撤回かつ有効な開始済みの接客は元の版を維持します。物件価格や参考金利が版をまたいで混ざることはありません。

物件価格を修正した場合は、「資料管理」の「案内に使用する資料本文」も原資料と照合してください。本文に明示された単一の `price: 数字` が登録価格と食い違う場合、公開プレビューと最終公開を止めます。正しい原資料を確認して業務候補を整理するか、新しいファイルへ差し替えてください。SDK 原文を自動で書き換える処理や、すべての文章の意味矛盾を検出する仕組みではありません。

## 差し替え・取り消し

同じ内容のファイルは SHA-256 で識別します。既存ファイルの利用か別資料としての登録かを社員が明示的に選びます。ファイル名だけで差し替え元を推測せず、自動上書き・削除・対客許可をしません。

未公開の更新は取り消せます。取り消しても、既存の原ファイル、SDK raw / normalized、確認記録、公開版は削除されません。

## 過去版の内容を再公開する

「公開バージョン履歴」で対象の版を開き、「vN の内容から復元草案を作成」を押します。草案を保存し、現在版との資料集合・価格等の違いを確認して、今も有効で対客利用が許可されていることを再検証して公開します。v1 → v2 → v1 の内容に復元する場合も、結果は新しい v3 です。v2 の削除や最新版ポインターだけの巻き戻しはしません。

期限切れ、社内専用、用途撤回、承認不足の資料は復元できません。社員が原因を解消するまではブロックされます。復元機能が期限や許可を補完することはありません。

## 今回の隔離環境

- Admin：`http://localhost:5176/admin`
- Customer：`http://localhost:5176/`
- Staff：`http://localhost:5176/staff`
- Backend：`127.0.0.1:8003`
- DB：`evidence/phase2_document_update/ui-test.db`
- Upload：`evidence/phase2_document_update/ui-uploads/`
- 起動：`scripts/phase2_document_update_test_server.py`

SDK 解析と業務サービスは実装本体です。AI の回答は明示した TEST provider で、有料 AI / TTS を使いません。実マイク、実音声、自然度の検証ではありません。人工修正した価格や条件は TEST データで、実際の公開事実や貸付条件ではありません。

実測結果と画面は `evidence/phase2_document_update/` に保存しています。[Chrome 画面一覧](../evidence/phase2_document_update/index.html) と [検証記録](../evidence/phase2_document_update/acceptance.md) を参照してください。通常 DB の切り替えは今回実行しません。

API と保存構造の詳細は [DOCUMENT_UPDATE_API.md](DOCUMENT_UPDATE_API.md)、通常環境の後続更新方法は [DOCUMENT_UPDATE_NORMAL_UPGRADE.md](DOCUMENT_UPDATE_NORMAL_UPGRADE.md) を参照してください。
